# مقرر اللجنة العلمية

تطبيق ويب داخلي بواجهة عربية كاملة واتجاه RTL، لإدارة طلبات اللجنة العلمية ودراستها وإعداد مسودات محاضرها.

**الجهة:** جامعة الجوف — كلية العلوم الطبية التطبيقية — قسم علوم المختبرات الإكلينيكية.

> **إصدار أولي عملي (0.1.0)** يعمل محليًا لمستخدم واحد. لا يتضمن تسجيل دخول ولا صلاحيات ولا تعدد مستخدمين.

---

## 1. حدود هذا الإصدار — اقرأها أولًا

هذه الحدود حقيقية ومقصودة، والتطبيق يعرضها في واجهته بدل إخفائها:

| الحد | الحالة |
|---|---|
| **اللوائح الفعلية** | وصلت الأصول وطابقت بصماتها، لكن **لا تحتوي طبقة نص صالحة** (ممسوحة ضوئيًا أو بطبقة OCR مشوّهة). **لم يُستخرج أي متطلب ولم تُعتمد أي قاعدة.** يلزم إدخال نص الصفحات يدويًا واعتماده أولًا — التفصيل في [`docs/ASSET_INTAKE.md`](docs/ASSET_INTAKE.md). |
| **النموذج الرسمي للمحضر** | **مربوط.** التصدير يفتح ملف النموذج نفسه ويعيد كتابة نص المستند فقط؛ 22 من 23 جزءًا تبقى مطابقة بايتًا ببايت. تُحقق بصريًا بمقارنة الأصل بالمخرج، ولم يُختبر الفتح في Microsoft Word بعد. |
| **التحليل الآلي** | اختياري. بلا مفتاح في بيئة الخادم يعرض التطبيق «التحليل الآلي غير مفعّل» ويعمل يدويًا بالكامل، ولا يستبدل النتائج بتحليل وهمي. |
| **الصلاحيات والدخول** | لا يوجد. التطبيق يستمع على `127.0.0.1` فقط. أي استخدام مؤسسي متعدد المستخدمين يحتاج مصادقة وصلاحيات وتدقيقًا، وهي غير مطبقة هنا. |
| **OCR** | غير مدمج. الملفات الممسوحة ضوئيًا تُعلَّم بأنها تحتاج OCR أو إدخالًا يدويًا، ولا تُرسل إلى أي خدمة خارجية تلقائيًا. مسار الإدخال اليدوي لكل صفحة متاح، ولا يصير سندًا إلا باعتماد مراجع. |

### ما لا يفعله التطبيق أبدًا

- لا يخترع قاعدة نظامية ولا مادة ولا تاريخ نفاذ ولا استثناء.
- لا يعرض استنتاجًا مسنودًا باستشهاد لم يُتحقق منه برمجيًا: أي معرّف غير موجود يُرفض، وأي اقتباس غير موجود حرفيًا في نص المقطع يُحذف وتُخفَّض النتيجة إلى «غير قابل للتحقق».
- لا يعتبر نقص الدليل «عدم استيفاء».
- لا يرجّح بين مصدرين متعارضين، ولا يحسم علاقة تعديل/استبدال من تلقاء نفسه.
- لا يحوّل بين التقويم الهجري والميلادي، ولا يحتسب أيامًا بقاعدة غير منصوص عليها.
- لا يشتق فئة مكافأة من ربع تصنيفي: **Q1 ليست «فئة أ»**.
- لا يحتسب أي صرف مالي.
- لا يُنشئ حضورًا ولا تصويتًا ولا توقيعًا ولا اعتمادًا، ولا ينسخها من نموذج أو اجتماع سابق.
- لا يرسل مراسلات ولا قرارات إلى أي جهة خارجية.
- يعامل نصوص المرفقات واللوائح **بيانات لا تعليمات**؛ وأي توجيه مضمّن داخلها يُبلَّغ عنه ولا يُنفَّذ.

## 2. التشغيل

### المتطلبات
- Node.js 20.10 أو أحدث (جُرّب على 22).
- npm 10 أو أحدث.

### الخطوات

```bash
cd scientific-committee-app

# 1) تثبيت الاعتماديات (الخادم والواجهة معًا)
npm install

# 2) إعداد البيئة
cp .env.example .env      # ثم عدّل القيم عند الحاجة

# 3) فحوص سريعة
npm run typecheck         # فحص الأنواع للخادم والواجهة
npm test                  # اختبارات الخادم

# 4) التشغيل أثناء التطوير (نافذتان)
npm run dev:server        # الخادم على http://127.0.0.1:4000
npm run dev:web           # الواجهة على http://127.0.0.1:5173

# أو: تشغيل الإصدار المبني من عملية واحدة
npm run build
npm start                 # يخدم الواجهة والـ API معًا على المنفذ 4000
```

ثم افتح `http://127.0.0.1:5173` أثناء التطوير، أو `http://127.0.0.1:4000` بعد البناء.

### متغيرات البيئة

كلها موثقة في `.env.example`. أهمها:

| المتغير | الغرض |
|---|---|
| `PORT` / `HOST` | منفذ وعنوان الخادم. `HOST` يبقى `127.0.0.1` للتشغيل المحلي. |
| `DATA_DIR` | مجلد قاعدة البيانات والملفات المرفوعة (مستبعد من git). |
| `MAX_UPLOAD_MB` | الحد الأقصى لحجم الملف المرفوع. |
| `AI_API_KEY` | مفتاح خدمة التحليل الآلي. **يُقرأ من الخادم فقط ولا يصل المتصفح.** فارغ = التحليل الآلي غير مفعّل. |
| `AI_PROVIDER` / `AI_BASE_URL` / `AI_MODEL` | المزوّد قابل للاستبدال (`anthropic` أو أي خدمة متوافقة مع `chat/completions`). |

**تنبيه:** لا تستخدم اشتراك Claude Code أو أي جلسة مساعد كمفتاح لهذا التطبيق؛ التطبيق يحتاج مفتاح API مستقلًا تديره الجهة.

**ما الذي يغادر التطبيق عند تفعيل التحليل؟** المقاطع النصية المستخرجة من اللوائح والمرفقات المختارة، وبيانات الطلب الوصفية — تُرسل إلى `AI_BASE_URL` فقط. لا تُرسل الملفات الأصلية. وبلا مفتاح لا تغادر أي بيانات الجهاز.

## 3. أول استخدام — بالترتيب

### (أ) ضبط الجهة والمسارات وتشكيل اللجنة
**الإعدادات** →
1. بيانات الجهة (تظهر في ترويسة المسودات المصدَّرة؛ لا يُستخدم شعار رسمي).
2. **مسارات الضوابط**: يوجد مساران مدمجان — «حضور/مشاركة في مؤتمر أو ندوة» و«مكافأة التميز» — ويمكن إضافة غيرهما. ضوابط كل مسار مستقلة تمامًا ولا تُسحب على مسار آخر.
3. **تشكيل اللجنة**: الأسماء والصفات. هذه القائمة **مصدر واحد** لجدول الحضور وجدول التوقيع في كل محضر، فلا يختلف اسم بينهما.
4. **أنواع الطلبات**: لكل نوع مسار إلزامي وقائمة تحقق بالمرفقات المطلوبة.

### (ب) إضافة لائحة
**مكتبة اللوائح** → «رفع مصدر جديد» → اختر الملف، واكتب العنوان والجهة والإصدار وتاريخ النفاذ **والمسار**، ويمكن إدخال بصمة SHA-256 المتوقعة ليقارنها التطبيق بالملف المستلم ويعلن عدم التطابق بدل اعتماده.

ثم من صفحة المصدر:
- راجع المقاطع وجودة نصها. المقطع لا يصلح سندًا إلا إذا اجتاز نصّه فحص الجودة، أو أُدخل نصه يدويًا **واعتمده مراجع**.
- **الملفات الممسوحة أو ذات OCR المشوّه:** استخدم «إدخال/مراجعة نص يدوي» لكل صفحة. النص اليدوي مرتبط برقم الصفحة وببصمة الملف، فإن استُبدل الملف توقّف سريانه تلقائيًا. لا يصبح سندًا قبل الاعتماد.
- «استخراج متطلبات مرشحة» (يحتاج التحليل الآلي مفعّلًا) أو أضف المتطلبات يدويًا.
- سجّل **علاقات المصادر** (يعدّل / يحلّ محل / يفسّر / يتعارض مع) بين لائحة وأخرى. أي علاقة غير محسومة تمنع إصدار دراسة نهائية في مسارها.

### (ج) اعتماد المتطلبات
**مراجعة المتطلبات** → راجع كل متطلب مقابل اقتباسه وموضعه، **حدّد مساره**، ثم اعتمده. المتطلب غير المعتمد لا يدخل أي مصفوفة مطابقة، والمتطلب بلا مسار لا يُطبَّق على أي طلب.

### (د) إضافة النموذج الرسمي
**النماذج** → ارفع ملف النموذج فور استلامه. تعرض الشاشة هيكل نموذج المحضر المطبَّق في التصدير، والخطوات اللازمة لربط الحقول بالقالب لاحقًا.

### (هـ) إنشاء طلب ودراسته
**الطلبات** → «طلب جديد» (رقم مرجعي، نوع، تاريخ التقديم مع تقويمه، العام الدراسي) → ارفع المرفقات ووسمها لتُحتسب في قائمة التحقق → سجّل بيانات الأبحاث/المشاركات/الإنجاز بحسب المسار → «فتح دراسة جديدة».

في شاشة الدراسة: أسباب عدم الجاهزية، تعارض المصادر، التحليل الآلي (إن كان مفعّلًا)، مصفوفة المطابقة، الملخص والمذكرة والتوصية المبدئية ومسودة بند المحضر، وسجل تعديلات المراجع. التصدير: مسودة عربية للطباعة (HTML) وملف DOCX.

### (و) المحاضر
**المحاضر** → مسودة جديدة → سجّل الحضور لهذا الاجتماع (لا يُنسخ من اجتماع سابق) → أدرج بنود الدراسات أو بنودًا مستقلة مع الجهة ذات العلاقة → صدّر.

**خياران للتصدير:**

| الخيار | متى يظهر | ماذا ينتج |
|---|---|---|
| **تصدير على النموذج الرسمي** | عند تسجيل نموذج رسمي في شاشة النماذج | يفتح ملف النموذج نفسه ويعيد كتابة نص المستند فقط. الترويسة وصورها والتذييل والأنماط والترقيم والسمة وإعداد الصفحة واتجاه RTL تبقى كما هي. يُرفض أي ملف لا يطابق هيكل النموذج بدل إنتاج مستند لا يطابقه. |
| **مسودة DOCX عامة** | دائمًا | مستند مبني من الصفر بترتيب أقسام النموذج، دون ادعاء مطابقة تنسيقه. |

التطبيق يعرض قبل التصدير ما سيُعبَّأ، وأي انحراف عن القالب، وأي تنبيه (مثل عدم تأكيد المخاطب في «رابعاً»).

## 4. وضع العرض التجريبي

مبدّل النطاق أعلى الشاشة: **العمل الفعلي** / **عرض تجريبي**.

بيانات العرض اصطناعية بالكامل، معلَّمة «للتجربة فقط — ليست لائحة معتمدة»، ومعزولة تمامًا: لا تظهر في النطاق الفعلي، ولا يمكن الاستشهاد بمتطلب تجريبي في دراسة فعلية (يرفضه التحقق البرمجي)، ولا إدراج دراسة تجريبية في محضر فعلي. تُنشأ وتُحذف من اللوحة الرئيسية أو الإعدادات.

## 5. البنية

```
scientific-committee-app/
├── server/                 # Node + Express + SQLite (TypeScript)
│   ├── src/routes/         # واجهات البرمجة
│   ├── src/services/       # الاستخراج، جودة النص، التحقق من الاستشهادات، الجاهزية، التصدير
│   ├── src/services/ai/    # مزوّد الذكاء الاصطناعي (من جهة الخادم فقط)
│   ├── src/demo/           # بيانات العرض الاصطناعية
│   └── src/tests/          # 75 اختبارًا
├── web/                    # React + Vite (TypeScript) — واجهة عربية RTL
└── data/                   # قاعدة البيانات والملفات المرفوعة — مستبعدة من git
```

### ما يُحفظ في git وما لا يُحفظ

| يُحفظ | لا يُحفظ |
|---|---|
| الكود، بيانات العرض الاصطناعية، الوثائق | `data/` كاملًا: قاعدة البيانات والملفات المرفوعة |
| `.env.example` بلا أسرار | `.env` والمفاتيح |
| — | نصوص اللوائح، وأسماء أعضاء اللجنة، والمرفقات، والمخرجات المصدَّرة |

**المستودع قد يكون عامًا.** لا تضع في أي ملف داخله محتوى لائحة، ولا اسم عضو لجنة، ولا مرفق طلب.

## 6. ضوابط الأمان في هذا الإصدار

- الرفع محدود بامتدادات معروفة؛ الملفات القابلة للتنفيذ أو التفسير في المتصفح (`.js`, `.html`, `.svg`, `.exe`, …) مرفوضة.
- يُخزَّن كل ملف باسم يولّده الخادم، ولا يُستخدم اسم المستخدم في المسار؛ وقراءة الملفات محمية من اجتياز المسار.
- التنزيل دائمًا بوصفه ملفًا (`Content-Disposition: attachment` + `nosniff`)، فلا يُفسَّر محتوى مرفوع داخل التطبيق.
- أسماء الملفات تُنظَّف من محارف التحكم وعلامات الاتجاه (بعض الأسماء العربية تصل مسبوقة بمحرف RTL).
- `CORS` مقصور على المضيف المحلي، والخادم يستمع على `127.0.0.1` افتراضيًا.

## 7. الاختبارات

`npm test` — 75 اختبارًا (Vitest + Supertest)، تغطي:

| المجال | أمثلة |
|---|---|
| الطلبات | الحفظ والاسترجاع، منع تكرار الرقم المرجعي، التحقق من المدخلات |
| الاستخراج | ملف نصي مدعوم، امتداد غير مدعوم، DOCX بلا نص |
| **جودة النص** | كشف OCR المشوّه، كشف العلامة المائية، **رفض تحويل نص مشوّه إلى سند** إلا بنص يدوي معتمد، كشف النص العربي الخارج بأشكال العرض، وعدم اعتبار المستند الإنجليزي نصًا مشوّهًا |
| **فصل المسارات** | ضوابط المؤتمرات لا تُطبَّق على مكافأة التميز، ورفض متطلب بلا مسار |
| الاستشهادات | رفض معرّف غير موجود، حذف اقتباس غير مطابق وخفض النتيجة، رفض مرفق من طلب آخر |
| الجاهزية | غياب المصادر يمنع نتيجة حاسمة، **علاقة تعديل غير محسومة تمنعها**، نقص المرفق ليس عدم استيفاء، ربط المرفق ببند قائمة التحقق ورفض بند خارجها |
| التعارض | كشف تعارض مصدرين، منع الإصدار، رفع الحظر بتوجيه مكتوب مسجَّل |
| **التصنيفات** | **Q1 لا تساوي فئة أ**، وفصل التقويم الهجري والميلادي والعام الدراسي |
| **المحاضر** | الحضور والتوقيع من تشكيل واحد، عدم نسخ الحضور من اجتماع سابق، الأقسام الستة، ربط الجهة بالبند |
| التحليل الآلي | مسار كامل مقابل مزوّد بديل: يقبل المسنود ويرفض المختلق |
| الأمان | اجتياز المسار، الامتدادات المرفوضة، تنظيف أسماء الملفات |
| التصدير | حفظ أسطر المذكرة فقرات مستقلة في HTML و DOCX بدل دمجها |

**ما لم يُختبر:** لا توجد اختبارات واجهة آلية (فُحصت الواجهة يدويًا عبر البناء ومسار API كامل)، ولم يُختبر فتح المخرجات في Microsoft Word (العرض تم عبر LibreOffice بخطوط بديلة).

## 8. النشر المؤسسي لاحقًا

هذا الإصدار **غير جاهز** للاستخدام المؤسسي متعدد المستخدمين. يلزم قبله:

1. مصادقة وهوية (SSO الجامعي) وصلاحيات بالأدوار (مقرر/عضو/قارئ).
2. سجل تدقيق مرتبط بهوية حقيقية بدل «مراجع محلي».
3. قاعدة بيانات مركزية بنسخ احتياطي واستعادة، وتشفير التخزين.
4. HTTPS ومراجعة أمنية، ومعالجة الرفع في بيئة معزولة.
5. سياسة احتفاظ بالبيانات، ومراجعة خصوصية لما يُرسل إلى أي خدمة تحليل خارجية، وموافقة الجهة عليها.
6. مطابقة مخرج واحد على النموذج داخل Microsoft Word بالعين قبل الاعتماد الرسمي.
7. حلّ لإدخال نصوص اللوائح الممسوحة (OCR مؤسسي أو إدخال يدوي معتمد) قبل تشغيل الدراسة الفعلية.
